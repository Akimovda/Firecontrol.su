# Память проекта: firecontrol

Этот файл — рабочая память проекта. Сюда записываются: суть проекта, принятые решения,
договорённости, известные проблемы и ссылки на артефакты. Обновляется по ходу работы.

## Что это за проект

Инструменты для публикации статей на сайт WordPress (тематика — пожарная безопасность:
СОУЭ, сигнализация и т.п., судя по примерам в коде) через REST API, сразу с SEO-полями
(Yoast / Rank Math) и FAQ-блоком (видимый + JSON-LD Schema.org).

## Файлы

- `wp_publish.py` — CLI-скрипт публикации.
  - Вход: markdown-файл (`--file`) или stdin.
  - Конвертирует markdown → HTML, добавляет FAQ (видимый `<h2>/<h3>/<p>` блок + `FAQPage` JSON-LD).
  - Создаёт пост в WP через `wp-json/wp/v2/posts`, по умолчанию статус `draft`.
  - Умеет: категории/теги (создаёт при отсутствии), обложку (локальный файл или URL),
    SEO title/description/focus keyword под Yoast или Rank Math (автоопределение плагина
    через `wp-json/` namespaces, либо явно `--seo-plugin`).
  - Настройка через переменные окружения: `WP_URL`, `WP_USER`, `WP_APP_PASSWORD`
    (WordPress Application Password, не основной пароль).
- `wp-seo-rest-meta.php` — must-use плагин для WordPress (кладётся в `wp-content/mu-plugins/`,
  активация не нужна). Регистрирует защищённые SEO-мета-поля Yoast/Rank Math с
  `show_in_rest => true`, иначе REST API не может их записать. Доступ на запись — только
  пользователям с правом `edit_posts`.

## Важные зависимости между файлами

Без установленного на сайте `wp-seo-rest-meta.php` скрипт `wp_publish.py` всё равно создаст
пост и FAQ, но SEO-поля молча не запишутся (скрипт это детектит и предупреждает в выводе).

## Файлы (доп.)

- `wp_audit.py` — SEO-аудит опубликованных постов через REST API: тонкий контент,
  SEO title/desc, обложка+alt, alt у картинок в тексте, дубли H1/отсутствие H2.
  Сортирует по приоритету (скор). `--csv`/`--json` сохраняют полный отчёт.
- `wp_linkmap.py` — карта внутренних ссылок между постами и страницами: считает
  входящие/исходящие internal-ссылки, находит "сироты" (0 входящих). Отдаёт только
  сырые данные графа — смысловые рекомендации "откуда сослаться" делаются вручную/LLM
  по выгруженным заголовкам и выжимкам контента.

## Артефакты

- `reports/audit.csv`, `reports/audit.json` — полный аудит 31 опубликованного поста
  (2026-08-06). Топ-проблемные: id 280, 362, 298, 253, 291 (тонкий контент + нет SEO
  title + нет alt у обложки). У ВСЕХ 31 постов не заполнен alt у featured-картинки —
  системная проблема, а не единичный случай.
- `reports/linkmap.json` — карта внутренних ссылок (2026-08-06). 56 опубликованных
  элементов (31 пост + 25 страниц), 36 без единой входящей внутренней ссылки.
  Изолированные коммерческие страницы услуг (0 входящих и почти 0 исходящих):
  `/special-technical-conditions/` (СТУ), `/videonablyudenie/`, `/fire-alarm-systems/`,
  `/proektirovanie-slabotochnyh-sistem/`. Хороший пример кластера ссылок для
  подражания — `/evacuation-plans/` (7 входящих, 12 исходящих, статьи про планы
  эвакуации плотно связаны друг с другом и с услугой).

## Правило: секреты

Секреты (WP_APP_PASSWORD, токены и т.п.) — только в `.env`, никогда не в память (memory)
и не в код. `.env` обязательно должен быть в `.gitignore`.
